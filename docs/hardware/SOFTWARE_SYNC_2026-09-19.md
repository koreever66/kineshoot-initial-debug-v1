## 1. 已知通过项

- USB 供电下，START 和 BOOT 两次静止采集均通过。
- 两次 USB 数据均约 2269 到 2270 行，采样率约 226.9Hz，最大间隔小于 6.32ms。
- I2C 固定地址诊断持续返回 `tx=0, rx=1, who=0xEA`。
- 重新上传 F4 后，充电宝模式两次桌面静止采集恢复有效，均约 2270 行。
- 恢复后的两次数据无采样缺口、无饱和，重力模长约 997 到 999mg。
- 软件端 action-chain 会话已包含 6 次有效采集，并已加入 0 行空采集文件拒绝逻辑。

## 2. 当前开放问题

### P0：切换供电后出现空表头采集

第一次从 USB 切到充电宝后，连续三次采集都只有 64 字节 CSV 表头，数据行为 0。重新检查连接并重刷 F4 后恢复，因此当前证据指向连接稳定性或供电切换过程，而不是采样算法。

### P0：四线连接器、NCS、AD0 的机械稳定性

需要确认轻拨线束时：

- SDA/SCL 不中断。
- 地址始终保持 `0x68`；不出现 `0x0C`。
- `NCS` 与 `VCC` 保持导通。
- `AD0` 与 `GND` 保持导通。

### P1：ICM 端供电稳定

需要实测：

- ICM `VCC` 对 `GND` 约 3.3V。
- 充电宝接入、线束轻拨和静止记录期间没有明显跌落。
- `GND` 共地稳定。

### P1：从充电宝切回 USB 的冷启动时序

软件端观察到从充电宝切回 USB 后，连续三次按 RST 蓝灯未亮，第四次恢复。需要统计五次冷启动，区分 USB 枚举延迟、复位时序和 IMU 初始化重试。

## 3. 硬件端复测顺序

### 测试 A：I2C 静态稳定性

1. 只用电脑 USB 给 ESP32 供电。
2. 运行 I2C 扫描。
3. 轻拨四根 PH2.0 线束。
4. 轻拨 ICM 端 `NCS` 和 `AD0` 跳线。
5. 观察 2 到 3 分钟。

通过标准：

- [ ] 地址保持 `0x68`。
- [ ] `WHO_AM_I=0xEA` 稳定。
- [ ] 不出现 `0x0C`。
- [ ] 无通信中断。

### 测试 B：端点和供电测量

断电通断检查：

- [ ] `NCS` 对 `VCC` 导通。
- [ ] `AD0` 对 `GND` 导通。
- [ ] `VCC` 对 `GND` 不导通。
- [ ] SDA 对 GND 不导通。
- [ ] SCL 对 GND 不导通。

上电电压检查：

- [ ] ICM `VCC` 约 3.3V。
- [ ] ICM `GND` 与 ESP32 `GND` 共地。
- [ ] 轻拨线束后电压仍稳定。

### 测试 C：USB 静止采集

- [ ] 10 秒静止 BOOT 采集约 2269 行。
- [ ] `write_failed=0`。
- [ ] 无 ERR、无 reset。
- [ ] 最大间隔小于 10ms。

### 测试 D：充电宝静止采集

- [ ] 切换前先关闭或断开负载。
- [ ] 充电宝 5V 接入后等待 10 秒。
- [ ] 只做一次站立静止 10 秒采集。
- [ ] 约 2269 行，不能是 64 字节空表头。
- [ ] 轻拨线束时数据不中断。

### 测试 E：五次冷启动记录

每次按以下顺序执行：

```text
1. 拔掉 USB。
2. 等待 10 秒。
3. 重新插入 USB。
4. 等待 5 秒。
5. 只按一次 RST。
6. 最多等待 10 秒。
```

每次记录：

```text
第几次：
USB 插入后 COM5 出现时间：
按 RST 前灯色：
按 RST 后灯色：
串口首行：
IMU_INIT 状态：
是否一次恢复：
失败时是否有红灯：
失败时是否有 COM5：
```

通过标准：

- [ ] 连续五次冷启动都恢复。
- [ ] 或者明确记录失败模式，并证明失败原因不是接触不良。

## 4. 动态测试门槛

满足以下条件后，才继续举臂、蹲起和投篮动态测试：

- [ ] 充电宝模式下连续两次静态采集均约 2269 行。
- [ ] 最大间隔小于 10ms，20ms 以上缺口为 0。
- [ ] `write_failed`、饱和和复位均为 0。
- [ ] 五次冷启动达到五次成功，或失败原因已定位。
- [ ] 轻拉线束和切换供电时 ICM 数据通路不失效。
