## 0. 关键背景：为什么一开始没有采购升压模块

最初 H1 硬件基线的供电方式是：

```text
充电宝 5V -> 电源开关 -> ESP32 5V
```

因为充电宝已经输出 5V，所以早期采购清单不需要 `3.7V -> 5V` 升压模块。最初的物料重点只是面包板、杜邦线、ESP32、ICM 和基础采集。

后来硬件方案从 H1 台架测试向 H2 可穿戴设备推进，开始采用：

```text
3.7V 锂电池 -> TP4057 -> 电源开关 -> ESP32
```

这个硬件供电树存在一个被漏掉的接口：

```text
TP4057 输出只有约 3.0 到 4.2V
ESP32 开发板 5V 引脚需要稳定 5V
```

今天下午与软件端同步接口、统一基线和检查完整供电链时，才发现早期采购中没有包含升压模块。这个问题不是软件采样、地址或数据格式问题，而是硬件供电架构从“充电宝 5V”切换到“锂电池可穿戴”后，采购 BOM 没有同步更新导致的遗漏。

最终修正方案：

```text
500mAh 电池 -> TP4057 -> SS-12E07G4 3A开关 -> TPS61088 固定5V -> ESP32 5V
```

同时不再需要 P-MOS、AO3415、100k 和 1k 电阻。

记录这条时间线的原因：

- 采购必须以冻结后的完整供电树为基准。
- 软件接口、硬件接口和电源接口必须在采购前同步。
- 不能只根据早期 H1 的充电宝方案推导 H2 可穿戴物料。
- 后续任何供电路径变化都必须重新检查 BOM。

软件测试供电边界补充：

```text
软件当前测试：电脑 USB 或充电宝 5V 直接给 ESP32
H2 集成测试：电池 -> TP4057 -> 3A开关 -> TPS61088 -> ESP32
```

因此 P-MOS 与直接 3A 开关的选择属于 H2 硬件实现，不影响当前软件接口测试。软件测试只需要 ESP32 5V、BOOT/RST、GPIO48 RGB 和 USB CDC 行为符合基线。

## 2. 固定接口和不可修改项

```text
ICM VCC  -> ESP32 3V3
ICM GND  -> ESP32 GND
ICM SDI/SDA  -> ESP32 GPIO8
ICM SCLK/SCL -> ESP32 GPIO9
ICM NCS  -> ESP32 3V3
ICM AD0  -> ESP32 GND

I2C address = 0x68
I2C clock   = 50kHz
WHO_AM_I    = 0xEA
```

硬件不得静默修改：

- 引脚定义。
- PH2.0 4P 线序。
- `NCS` 和 `AD0` 固定电平。
- 地址、I2C 时钟和数据格式。
- 3.3V 电源路径。
- 软件 F4 的记录时长、量程、触发方式和采样逻辑。

## 3. 今天遇到的难点

### 3.1 旧调试基线与新软件基线冲突

问题：

- 旧记录中存在 `0x69`、`0x0C`、`100kHz` 和 `0x68/0x69` 自动探测。
- 新软件基线要求固定 `0x68`、`50kHz` 和 `WHO_AM_I=0xEA`。

影响：

- 如果继续沿用旧固件和旧地址，硬件测试结果不能作为当前 F4 基线证据。

解决：

- 将所有硬件当前文档更新为新基线。
- 旧内容保留为历史记录，不再作为当前目标。
- 禁止用 `0x69` 或 `0x0C` 作为长期主地址。

状态：已解决，待实物复测。

### 3.2 NCS 和 AD0 的连接方式

问题：

- 如果 NCS 或 AD0 悬空，通信可能不稳定。
- 增加这两根线后，是否必须换成 6P 连接器。

解决：

- `NCS -> 3V3`、`AD0 -> GND`，在 ICM 端就近固定。
- 固定电平后只保留 VCC、GND、ICM SDI/SDA、ICM SCLK/SCL 四根线。
- 现有 PH2.0 4P 足够，不需要采购 6P。

状态：方案已确定，待焊后万用表验证。

### 3.3 面包板和杜邦线接触不稳定

问题：

- 面包板阶段的 I2C 曾出现通信异常、固定饱和和异常值。
- 投篮动作振动会让排针、面包板和杜邦线接触变化。

影响：

- 数据质量不可信，可能误判为传感器或算法问题。

解决：

- 改用 26AWG 柔性线和 PH2.0 连接器。
- 焊接焊点并做应力释放。
- 连续扫描至少 5 分钟，再做 10 秒记录和动态测试。

状态：待配件到货后执行。

### 3.4 充电模块选型

问题：

- 常见 TP4056 模块充电电流为 1A。
- 500mAh 电池用 1A 充电约为 2C，偏大。

解决：

- 选择 TP4057-500mA 版本。
- 电池最大充电倍率为 1C，即 500mA，和 TP4057-500mA 匹配。
- 实际订单购买 2 个 TP4057 模块。

状态：已采购，待充电测试。

### 3.5 升压模块选型

问题：

- H1 原方案由充电宝直接提供 5V，采购时没有升压模块。
- 切换到 H2 电池可穿戴后，TP4057 输出只有电池电压，不能直接接 ESP32 5V。
- TP4057 输出是电池电压，不能直接给 ESP32 的 5V 引脚。
- 便宜的 3.7V 转 5V 模块有些只有电位器，可能有电压漂移。

解决：

- 下午与软件端同步完整供电链接口时确认了这个缺口。
- 追加采购 TPS61088 固定 5V 版本。
- 选择 TPS61088 固定 5V 版本。
- 使用 5V 跳线锁定，不使用电位器长期调压。
- 输入范围 `2.7-12V`，覆盖电池 `3.0-4.2V`。
- 3V 输入、5V 输出时表格标称最大输出约 `3.78A`。

状态：已采购，待空载和带载测试。

### 3.6 TPS61088 焊盘版和端子版差异

问题：

- 商品链接包含焊盘版和 KF301 螺丝端子版。
- 端子版约 10g，焊盘版约 5.4g。
- 端子版更厚，约增加 4 到 5mm。

解决：

- 穿戴设备优先焊盘版。
- 端子版只用于台架测试或临时方案。
- 到货后先确认版本，再决定是否焊接。

状态：订单为固定 5V 版本，焊盘/端子版仍待收货确认。

### 3.7 TPS61088 EN 不等于主电源开关

问题：

- EN 接 GND 只是关闭升压，不是完全断开输出。
- 关机状态下输出可能仍接近或略低于输入。

解决：

- EN 不作为主电源开关。
- 主开关放在电池正极路径。
- TPS61088 负责升压，不负责彻底断电。
- TP4057 不具备负载共享；充电时必须关闭负载，USB 烧录或导出时必须断开电池输出，避免双 5V 倒灌。

状态：已明确。

### 3.8 低电流开关不适合主路径

问题：

- 最初购买的 SS12D07VG4 额定电流约 0.5A。
- 升压输入峰值可能接近或超过 1A，不适合串联承载主电流。
- SS12D07VG4 的额定值仍必须以数据手册为准；在确认达到 1A 前，不得用于升压输入主路径。

解决：

- 放弃 SS12D07VG4 主路径。
- 采购 SS-12E07G4，1P2T，3A，5 只装。
- SS12D07VG4 仅作为备用或低电流控制。

状态：已采购，待装配验证。

### 3.9 成品 P-MOS 高边模块难以找到

问题：

- 许多所谓 MOS 模块是 N-MOS 低边，会切断公共地。
- F5305S 类模块标称受控输出 `5-36V`，不适合 `3.0-4.2V` 电池路径。
- 带 EN/CTRL 且明确支持 3.0V 的成品模块很难确认。

解决：

- 主方案改为 SS-12E07G4 3A 开关直接控制电池正极。
- 当前主方案不需要 P-MOS、100k、1k 或 AO3415。
- P-MOSFET + SS12D07VG4 作为回退方案保留，只有 SS-12E07G4 不适用时才启用。
- SS12D07VG4 不单独用于升压输入主电流路径。

状态：主方案已改为 3A 直接开关。

### 3.10 电池放电能力限制

问题：

- 商品页先显示放电倍率 `0.5C`。
- `0.5C × 500mAh = 250mA`，连续放电能力偏紧。
- 后续客服确认保护板为 `1C` 持续、`2C` 峰值。

最终参数：

```text
持续放电：1C = 500mA
峰值放电：2C = 1000mA
最大充电：1C = 500mA
过流保护点：商家不知道
```

影响：

- TPS61088 标称 2A，不能理解为电池可以持续提供 2A。
- ESP32 实际平均负载必须低于 500mA 电池输入。
- 启动瞬间电容充电峰值不能长期接近或超过 1A。

状态：电池可用，待实测启动和平均电流。

## 5. 配件到货后的装配顺序

### 阶段 0：开箱和验收

- 核对订单数量。
- 检查 PH2.0 是 2.0mm，不是 1.25mm 或 2.54mm。
- 检查电池是否鼓包、破损。
- 检查 TPS61088 是焊盘版还是端子版。
- 测量 TP4057、TPS61088、电池和开关的实际尺寸。

### 阶段 1：电池和 TP4057

- 自己焊接 PH2.0 2P 到电池线。
- 用万用表确认正负极。
- 先不接 ESP32，单独充电。
- 观察红灯充电、绿灯或红灯熄灭状态。
- 充完测量电池电压，应接近 4.2V。

### 阶段 2：开关和 TPS61088

- 将 SS-12E07G4 串到 TP4057 输出正极和 TPS61088 VIN+ 之间。
- TPS61088 只短接 `5V` 跳线。
- 不接 ESP32，空载测输出，目标约 5.00V。
- 接 ESP32，测启动和记录时是否低于 4.85V。
- 如果模块有 EN，保持 EN 为开启状态，不把 EN 当主开关。

### 阶段 3：ICM 柔性线束

- 焊接 ICM VCC/GND/SDI-SDA/SCLK-SCL。
- ICM 模块实际印字为 SDI/SCLK，文档统一写作 `SDI/SDA` 和 `SCLK/SCL`。
- NCS 就近接 3V3，AD0 就近接 GND。
- 焊到 PH2.0 4P，线长控制在 10 到 15cm。
- 用万用表逐根检查，不允许短路或接错。
- 上电前确认 ESP32 只通过 USB 供电。
- 运行 I2C 扫描，确认 `0x68` 和 `WHO_AM_I=0xEA`。

### 阶段 4：机械装配

- ICM 放入 5 × 3.5 × 1.8cm 小盒，盒底贴 EVA。
- 盒子贴到 3.8cm 腕带，位置在腕横纹上方 2 到 4cm。
- ESP32、TP4057、TPS61088、开关和电池单层放进 10 × 8cm 软袋。
- 用 5cm 前臂带固定，位置在腕横纹上方 5 到 10cm。
- 每个线束两端留缓冲弯，用胶带或扎带固定。

### 阶段 5：上电和静态测试

- 用万用表检查 VCC/GND、SDA/GND、SCL/GND 是否短路。
- 测量 ICM VCC 约 3.3V。
- 测量 NCS 约 3.3V。
- 测量 AD0 约 0V。
- 测量 TPS61088 输出约 5.0V。
- 做 10 秒静止测试。
- 采样率验收按 `210-240Hz` 或中位采样间隔 `4.0-4.8ms`，不要使用过窄的 220-225Hz 判定。

### 阶段 6：动态测试

- 小幅旋转和摆臂 2 分钟。
- 模拟投篮 10 次。
- 记录数据。
- 检查无复位、无全零、无固定饱和、无削顶。
- 采样间隔不超过 10ms。

- TPS61088 可能发成 KF301 端子版，重量和厚度增加。
- ESP32 和 ICM 实际厚度未测量。
- 10 × 8cm 软袋偏大，投篮时可能晃动。
- 50mm 前臂带不能完全覆盖 80mm 宽的软袋。
- PH2.0 和 26AWG 线束的应力释放尚未实装。
- 万用表和魔术贴等辅助物料尚未确认。

## 8. 禁止事项

- 不使用 `0x69` 或 `0x0C` 作为长期地址。
- 不允许 `NCS` 或 `AD0` 悬空。
- 不切换 ESP32 的 3.3V 电源路径。
- 不把 5V 接到 ICM VCC。
- 不在充电时让负载长期开启。
- 不把 TPS61088 EN 当主断电开关。
- 不在未测量 5V 的情况下直接接 ESP32。
- 不把带保护板的电池长期并联使用。
- 不把根目录旧 `firmware/`、`tools/`、`data/` 当作当前固件；它们已迁入 `legacy/`。

## 10. 当前结论

H2 第一版配件和电源方案已经确定，可以进入收货和焊接阶段。H2 当前仍为 `assembling_and_verification`，不能标记完成。当前最大剩余风险不在接线，而在电源峰值和电池保护板、TPS61088 启动浪涌以及机械尺寸。真实投篮前必须完成 10 秒静止、小幅动态、电源带载和接口复核。
